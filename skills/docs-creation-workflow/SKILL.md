# Documentation Creation Workflow

## When to Use This Skill

Use this skill when:

- Creating comprehensive technical documentation
- Designing information architecture for docs
- Writing API documentation, user guides, or tutorials
- Establishing documentation quality standards
- Planning documentation maintenance

## When NOT to Use This Skill

Do NOT use this skill when:

- Extracting documentation from code (use Docs Extractor mode)
- Writing application code
- Debugging issues

## Documentation Strategy Methodology

### Phase 1: Documentation Audit and Analysis

**1.1 Current Documentation Assessment**

- Audit existing documentation and identify gaps
- Assess documentation quality and completeness
- Identify outdated or obsolete documentation
- Assess documentation accessibility and usability

**1.2 Stakeholder Analysis**

- Identify all documentation stakeholders and users
- Document stakeholder needs and requirements
- Assess stakeholder skill levels and expertise

**1.3 Content Strategy Planning**

- Define documentation goals and objectives
- Identify content types and formats
- Define content tone and voice guidelines

### Phase 2: Documentation Architecture and Structure

**2.1 Information Architecture Design**

- Design documentation hierarchy and navigation
- Define content organization and categorization
- Design search and discovery mechanisms

**2.2 Documentation Types and Templates**

- API documentation templates
- User guide templates
- Technical specification templates
- Troubleshooting and FAQ templates

**2.3 Content Management Strategy**

- Content creation and review workflows
- Content versioning and change management
- Content publishing and distribution

### Phase 3: Technical Documentation Creation

**3.1 API Documentation**

- Comprehensive API reference documentation
- API endpoints, parameters, and responses
- Usage examples and code samples
- Authentication and error handling guides

**3.2 System Architecture Documentation**

- System overview and architecture diagrams
- Component relationships and interactions
- Deployment and infrastructure documentation

**3.3 Development Documentation**

- Development environment setup guides
- Coding standards and best practices
- Testing procedures and guidelines

### Phase 4: User-Focused Documentation

**4.1 User Guides and Tutorials**

- Comprehensive user guides and manuals
- Step-by-step tutorials and walkthroughs
- Onboarding and getting started guides

**4.2 Troubleshooting and Support**

- Troubleshooting guides
- Common issues and solutions
- FAQ and knowledge base content

**4.3 Release and Change Documentation**

- Release notes and changelogs
- Migration and upgrade guides
- Deprecation notices

### Phase 5: Documentation Quality and Standards

**5.1 Writing Standards and Guidelines**

- Technical writing standards and style guides
- Terminology and glossary standards
- Readability and accessibility guidelines

**5.2 Quality Assurance and Testing**

- Documentation review and approval processes
- Accuracy and completeness validation
- Usability testing and feedback collection

**5.3 Metrics and Analytics**

- Documentation usage and engagement metrics
- Content performance measurement
- User feedback and satisfaction metrics

### Phase 6: Documentation Maintenance and Evolution

**6.1 Maintenance Strategy**

- Maintenance schedules and procedures
- Content update and refresh processes
- Obsolete content identification and removal

**6.2 Evolution and Improvement**

- Documentation evolution and roadmap planning
- User feedback integration
- Technology and platform updates
