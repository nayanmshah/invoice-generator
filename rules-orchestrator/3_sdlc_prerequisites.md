# SDLC Prerequisites (Condensed)

**Validate before delegating.** Do not delegate until prerequisites are ready. If missing: delegate to the mode that produces them; include instruction to hand off to intended mode when done.

| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |

Brainstorm fetches context, presents it, deeply understands requirements with user (Q&A/brainstorm), then hands off to prd or architect per pipeline. | Entry mode; ask user. See context-input-handling.md.                       |
| **prd**                                   | User idea or draft (initial); initial-prd.md (refinement). **Greenfield:** Idea must be structured OR from brainstorm. **When JIRA/SOW:** Orchestrator delegates to brainstorm first, not directly to prd; brainstorm then hands off to prd. If minimal details (no JIRA/SOW): delegate to brainstorm first. See expertise-handoff.md and context-input-handling.md.                         | Entry mode; ask user; if minimal or JIRA/SOW → brainstorm first            |

## Downstream Prerequisites (Mode Handoffs)

| Mode                      | Prerequisites                                                                                                     | If Missing                                |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------- | ----------------------------------------- |
| **prototype**             | architecture.md, refined-prd or condensed scope, CONTEXT                                                          | Redirect to architect                     |
| **plan** (dev-plan phase) | architecture.md, refined-prd/scope, UX artifacts when UI                                                          | Redirect to architect or prototype        |
| **code**                  | development-plan.md (or bug-fix-scope for brownfield-fix-bug), architecture.md                                    | Redirect to plan or ask user (fix-bug)    |
| **qa**                    | development-plan.md (or bug-fix-scope for brownfield-fix-bug or refactor-scope for brownfield-refactor), codebase | Redirect to code; **MANDATORY — no skip** |
| **secure**                | development-plan.md (or bug-fix-scope for brownfield-fix-bug), codebase, code quality gate passed                 | Redirect to qa; **MANDATORY — no skip**   |
| **deploy**                | architecture.md, codebase, security-review.md, code-review.md, all sprints finished                               | Redirect; do not skip quality gates       |

**Brownfield-fix-bug:** **Debug** = debug phase (diagnose only; hands off to code). **Code** = code implementation phase (applies fix from debug or diagnose+fix in one flow). Delegate to qa with bug-fix-scope. After secure: ask user "Does this fix require deployment?" — if no, end pipeline; if yes, delegate to deploy.

## Validation Rule

1. Before delegating to mode X: Check mode X's prerequisites per table above.
2. If missing: Delegate to the mode that produces the missing artifact. Include instruction to hand off to mode X when done.
3. If present: Delegate with pipelineId and diagramSpec in new_task message.

**Direct mode entry:** When user selects a mode directly (e.g., Code, Plan) instead of following /greenfield or /brownfield, that mode runs expertise check on every message (per .nayan/guidance/expertise-handoff.md), then self-validates prerequisites per sdlc-prerequisites. If missing, it redirects to the producing mode via new_task.

**Explicit UI change:** When the user explicitly requests a change in UI (redesign, look-and-feel, design system, component/layout changes), ensure prototype (create/update) → plan (create/update) run first before code; use architect (create/update) only when there is API or architecture impact. Applies to both greenfield and brownfield. See .nayan/guidance/pipeline-entry-points.md.

**Full reference:** sdlc_prerequisites rule (in .nayan/rules/); .nayan/guidance/expertise-handoff.md for handoff and expertise checks
